# PulseBoard — Real-Time Sales Analytics Platform

**[Live demo](https://abhishekjha66.github.io/pulseboard/)** · Medallion ETL → ML forecast → real-time dashboard

An end-to-end analytics project: a Bronze → Silver → Gold data pipeline with data-quality validation, a 30-day revenue forecast, and a real-time dashboard fed by a Node.js + Socket.IO event stream.

> **Note on data:** the dataset is synthetic (generated by `pipeline/generate_data.py`) with realistic defects injected on purpose — duplicates, missing values, mixed date formats, negative quantities and price outliers — so the cleaning layer has real work to do.

## Architecture

```
generate_data.py ──► BRONZE (raw, as-is + lineage cols)
                        │  dedupe · standardise text · parse mixed dates
                        │  validation rules → rejected rows counted by reason
                        ▼
                     SILVER (clean, typed, validated)
                        │  SQL aggregations
                        ▼
                     GOLD (daily · monthly · product · region · channel · hourly)
                        │                         │
                        ▼                         ▼
              Linear-regression forecast     docs/data/gold.json
                                                  │
 Node.js + Express + Socket.IO ──(order:new)──►  Dashboard (Chart.js)
   simulated order stream, rolling 60 s KPIs
```

## Features

- **Medallion pipeline** (Python, pandas, SQL on SQLite): 20,600 raw rows → 18,369 clean rows; every rejected record is counted by reason and the totals reconcile exactly (tested).
- **Data-quality rules:** duplicate orders, invalid timestamps, missing/non-positive quantity or price, and price outliers (> 5× product median).
- **Forecasting:** 30-day revenue forecast = linear-regression order volume (trend + weekday features) × average order value, with a 95% band. Scored on a chronological 80/20 hold-out: **orders R² 0.46, revenue MAPE ≈ 20%**. Daily revenue is noisy because a few big-ticket items dominate it, so I report that honestly rather than hiding it.
- **Real-time layer:** Express + Socket.IO server emits `order:new` events and pushes rolling-window KPIs every second; REST endpoints expose `/api/kpis`, `/api/orders/recent`, `/api/health`.
- **Dashboard:** auto-detects the Node server and streams over WebSocket; on static hosting (GitHub Pages) it falls back to an in-browser simulator so the live demo works with no backend.
- **Tests + CI:** pytest (pipeline) and `node --test` (server), run on every push, then auto-deploy to GitHub Pages.

## Quick start

```bash
# 1. Pipeline
pip install -r requirements.txt
python pipeline/generate_data.py        # -> data/raw_orders.csv
python pipeline/medallion.py            # -> data/pulseboard.db + docs/data/gold.json
pytest -q

# 2. Live server + dashboard (http://localhost:3000)
cd server && npm install && npm start
```

Open `docs/index.html` through any static server for the simulator-only mode, e.g. `python -m http.server -d docs`.

To point the hosted dashboard at your own deployed server: `https://abhishekjha66.github.io/pulseboard/?server=https://your-server.example.com`

## Project structure

```
pipeline/    generate_data.py · medallion.py   (Bronze/Silver/Gold + forecast)
server/      index.js · test.js                (Express + Socket.IO)
docs/        index.html · data/gold.json       (dashboard, served by GitHub Pages)
tests/       test_pipeline.py
.github/     workflows/deploy.yml              (CI + Pages deploy)
```

## Deploy to GitHub Pages (2 minutes)

1. Create a repo named `pulseboard` and push this folder to `main`.
2. Repo → **Settings → Pages → Source: GitHub Actions**.
3. The workflow runs tests and publishes `docs/`. Live at `https://<your-username>.github.io/pulseboard/`.

## Porting to Snowflake

The Silver/Gold SQL is plain ANSI-style (`GROUP BY`, `SUM`, `COUNT DISTINCT`). Swap `sqlite3` for the Snowflake connector, replace `substr(order_date,1,7)` with `TO_CHAR(order_date,'YYYY-MM')`, and schedule Silver/Gold with Snowflake Tasks.
